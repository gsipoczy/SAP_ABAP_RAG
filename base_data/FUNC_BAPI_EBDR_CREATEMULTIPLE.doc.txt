&FUNCTIONALITY&
This method enables you to delete external billing document requests
(EBDRs).
&HINTS&
Restrictions
It is not possible to delete an EBDR if one of the following conditions
applies:
It has already been billed
It has already been billed and reopened for billing (by billing document
cancellation)
It has been billed, cancelled, and rejected
Transfer
You must transfer the document numbers of the external billing document
requests that are to be deleted to the method as import parameters.
Within the BAPI_EBDR_DELETEMULTIPLE, a COMMIT is performed.

Return Messages
Messages are returned in the exporting parameter ET_MESSAGE and in the
exporting parameter RETURN.
A list of EBDR IDs that have been deleted successfully is provided in
the exporting parameter ET_DELETEDDOCNUMBER.
A list of EBDR IDs that cannot be deleted is provided in the exporting
parameter ET_DELETEFAILEDDOCNUMBER.

FU BAPI_EBDR_GETLIST
____________________________________________________
Functionality
This method expects you to provide a list of preceding document numbers
and the corresponding sender system.
For these preceding document numbers and the sender system, it will find
the corresponding list of external billing document request (EBDR)
document numbers and EBDR document item numbers.
Notes
The following authorization objects are checked with activity 03:
V_VBRK_VKO Billing: Authorization for Sales Organizations
V_VBRK_FKA Billing: Authorization for Billing Types

Transfer
You must transfer the document numbers of the preceding documents.

Return Messages
Messages are returned in the exporting parameter ET_MESSAGE and in the
exporting parameter RETURN.
The list of corresponding EBDR document numbers is provided in the
exporting parameter ET_BDRHEADER.
The list of corresponding EBDR document item numbers is provided in the
exporting parameter ET_BDRITEM.

&FUNCTIONALITY&
This method enables you to reject external billing document requests
(EBDRs).
Restrictions
It is not possible to reject an external billing document request has
already been billed.

Transfer
You must transfer the document numbers of the external billing document
requests to be rejected to the method as an importing parameter.
Within the BAPI_EBDR_REJECTMULTIPLE, a COMMIT is performed.

Return Messages
Messages are returned in the exporting parameter ET_MESSAGE and in the
exporting parameter RETURN.
 A list of external billing document requests (EBDRs) that have been
successfully rejected is provided in the exporting parameter
ET_REJECTEDDOCNUMBER.
A list of external billing document request IDs that cannot be rejected
is provided in the exporting parameter ET_REJECTFAILEDDOCNUMBER.


&FUNCTIONALITY&
You can use this BAPI to create external billing document requests
(EBDRs).
As input parameters, you are expected to enter information about the
items to be processed in the table IT_DATA. This data is processed and
creates EBDRs. You also have the option of transferring administrative
data in the input structure IS_ADMINISTRATION_DATA. You can also enter
optional conditions for the individual items to be processed in the
input table IT_CONDITION_DATA, as well as means of payment card
information in the table IT_PAYMENT_CARD. In the input table
IT_TEXT_DATA, you can enter texts.

Using the the input structure TESTRUN, you can set whether the BAPI
performs a test run.
This method can be used in the simulation run (TESTRUN = 'X') and also
in the update run, including the update (TESTRUN = ' '). Both execution
variants deliver any errors that occurr back to the output table RETURN.
In the simulation run, no COMMIT is performed.
Within the BAPI_EBDR_CREATEMULTIPLE BAPI, a COMMIT is performed.
Using the input parameter COMMIT_MODE in the control structure
is_control you can determine whether the COMMIT is performed
asynchronously (IV_COMMIT_MODE, = '1') or synchronously (IV_COMMIT_MODE,
 = '2').
Via the parameter PRECEDINGDOCUMENTCHECK in the control structure
is_control you can determine whether the whole EBDR is not created in
case of errors or only the items for which the errors occur.

Return Messages
Messages are returned in the exporting parameter ET_MESSAGE and in the
exporting parameter RETURN.
A list of EBDR IDs that have been created successfully is provided in
the exporting parameter ET_EBDRCREATEDDOC.
A list of EBDR items that have been created successfully is provided in
the exporting parameters ET_EBDRCREATEDDOCITEM.
A list of preceding document items for which no EBDRs can be created is
provided in the exporting parameter ET_EBDRCREATEFAILEDDOCITEM.
